# Команда: ai-session-start

## Назначение

Быстрый старт **новой сессии** в уже подключённом репозитории: восстановить контекст за
секунды, а не «раскопками». Новая сессия не должна заново разбираться, что за продукт и
кто ещё что-то меняет. Это runtime-команда: исполняет её среда (Claude Code и т.п.),
следуя порядку ниже; сам кит её не «запускает».

## Когда

В начале каждой новой сессии работы в репозитории. Если repo-context пуст — сперва
онбординг (`skills/repo-onboarding/SKILL.md`), затем эта команда.

## Порядок выполнения

1. **Manifest** — прочитать `.ai/managed/manifest/ai-ops-manifest.yaml`: версия кита,
   включённые workflow, скиллы, политики.
2. **Ярус 1 — читать ВСЕГДА** — прочитать документы контекста с `read_tier: 1` во
   frontmatter: как минимум `context/product/ProductStatus.md` (что реально готово/живёт
   в проде, что отложено — источник правды о «сейчас») и `context/now.md` (снимок на
   дату). Это анкер сессии; не анкорить задачу на нормативных документах, пока не
   сверился с фактическим статусом (`rules/core/ProductStatusPolicy.md`). Если снимок
   протух (freshness) — перепроверить до старта. Ярус 1 держится компактным (снимок
   ≤ ~2 КБ токенов); детали — в отдельных документах яруса 3, не в снимке.
3. **Ярус 2 — читать ПО ТЕМЕ задачи** — из `context/*` (read_tier: 2) прочитать только
   релевантное текущей задаче: UI-задача → `product/DesignSystem.md`; данные/интеграции →
   `system/*`; бизнес-правила → `product/BusinessRules.md` и т.д. **Не** читать `context/*`
   целиком: это раздувает стартовый контекст (см. `ai_ops_kit/context/context_cost.py` и бюджет
   `context_budget.session_start_tokens` в `.ai-ops.yaml`).
   **Ярус 3 — только по ЯВНОЙ необходимости** — крупные контракты и архивы
   (`read_tier: 3`, напр. `product/MetricCatalog.md`) читать лишь когда задача прямо их
   требует. Документ без `read_tier` трактовать как ярус 2 (по теме).
4. **Свежие решения** — последние эпизоды из `decisions/registry.yaml` (что уже решено и
   почему; необратимые решения).
5. **Текущая ветка и WorkItem** — определить активную ветку; если ей соответствует
   `features/<id>/workitem.yaml` — прочитать статус (`PYTHONPATH=.ai/managed python3 -m ai_ops_kit.lifecycle.workitem status`).
6. **Параллельные работы** — прочитать реестр активных работ
   (`PYTHONPATH=.ai/managed python3 -m ai_ops_kit.lifecycle.active_work list .ai/runtime/active-work.yaml`). Если текущая задача уже
   ясна — прогнать conflict forecast по её зонам
   (`PYTHONPATH=.ai/managed python3 -m ai_ops_kit.lifecycle.active_work check … --areas …`): предупредить о пересечении с другими
   сессиями ДО начала работы.
7. **Незавершённые проверки** — заглянуть в `.ai/runtime/` текущего прогона: открытые
   гейты/evidence.
8. **Состояние предыдущей сессии** — если есть `.ai/runtime/sessions/<id>/handoff.yaml`, прочитать
   его ПЕРВЫМ делом среди runtime-файлов: там цель прошлой сессии, что сделано, какие решения
   приняты, что открыто и следующий шаг. Файл пишется, когда кит советует сменить сессию
   (`ep-2026-08-19-session-handoff-scope-narrowed`), поэтому его отсутствие — норма, а не пробел;
   а если он есть, начинать без него значит платить за перечитывание истории заново.
9. **Пределы этой сессии** — спросить `ai-ops session`: контекст, расход и один из четырёх исходов
   (продолжать / сжать / очистить / новая сессия). Числа порогов объявлены СТАРТОВЫМИ и подлежат
   калибровке замером (`ep-2026-08-13-session-ceiling-and-context-thresholds`, п. 1 пакета
   `ep-2026-08-17-session-protocol`) — то есть их превышение это разговор, а не поломка.
   Кит СОВЕТУЕТ и не отказывает: решение продолжать остаётся за человеком
   (`enforcement=advise`, подтверждено владельцем 19.08.2026).
10. **Короткое понимание контекста** — показать человеку резюме на 5–8 строк: продукт (1
   строка), ветка+WorkItem+статус, активные параллельные работы и риск пересечения,
   что незакрыто. Затем начинать работу.

## Границы (честно)

- Команда **читает**, а не меняет. Автоматический запуск при старте сессии — поведение
  рантайма (через его механизм старта/`CLAUDE.md`), не гарантия кита; кит даёт порядок и
  инструменты, «само-срабатывание» — привязка на уровне рантайма
  (см. `manifest → session_orchestration`, `verified_against_deploy: false`).
- Общая продуктовая память (`context/*`, решения, knowledge graph) — читается; временное
  состояние другой сессии (её runtime, черновики) — **не** смешивать со своим.

## Результат

Короткое резюме контекста + осознанный старт: известны продукт, ветка, WorkItem, статус,
параллельные работы и риск пересечения.
