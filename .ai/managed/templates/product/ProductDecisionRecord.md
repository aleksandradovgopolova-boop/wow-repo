# Product Decision Record

Второй управляющий объект. Отвечает на вопрос **«какие варианты рассматривали и почему выбран этот»**.

Кладётся в `features/<workitem-id>/product-decision.yaml`.

```yaml
schema_version: 1
kind: ProductDecisionRecord

question: что именно решаем
opportunity: features/<workitem-id>/opportunity-brief.yaml   # решение без проблемы не бывает

# Вариантов ДВА И БОЛЬШЕ. Один вариант — это не решение, а оформление уже принятого; и минусы есть
# у каждого варианта, иначе его не рассматривали, а описывали.
options:
  - id: wizard
    summary: пошаговый мастер
    pros: [меньше когнитивной нагрузки на шаге]
    cons: [дольше для опытного пользователя]
    risks: [рост отказов на втором шаге]
  - id: single-form
    summary: одна форма с подсказками
    pros: [быстро для тех, кто знает, чего хочет]
    cons: [страшно выглядит для новичка]
    risks: []

recommendation: wizard          # рекомендация кита
owner_decision: wizard          # решение владельца; `deferred` + deferred_reason — тоже решение
confidence: medium              # low | medium | high

not_doing: >
  Не трогаем импорт из внешних систем: это отдельная проблема, и смешение сделало бы обе
  непроверяемыми.
revisit_when: >
  Если доля отказов на шаге выбора не упадёт ниже 25% за две недели — возвращаемся к single-form.
```

## Почему `revisit_when` обязателен

Решение без условия пересмотра нельзя ни подтвердить, ни отменить: через месяц спор о нём будет
спором о памяти. Условие пересмотра — то, что превращает решение в проверяемое утверждение.
