# DelegationPolicy — культура делегирования разведки (v3.17.0)

## Зачем

Тяжёлые для контекста работы (разведка по всему репозиторию, разбор больших логов, сравнение многих
файлов) не должны выполняться в ОСНОВНОЙ сессии: их результаты оседают в контексте до самого её конца,
и каждый следующий запрос заново оплачивает это чтение. Их место — в **отдельном краткоживущем контексте**
(сабагент), из которого в основную сессию возвращается только **сводка**.

## Что делегируется по умолчанию

```
repository_wide_exploration   разведка по всему репозиторию
large_log_analysis            разбор больших логов
many_file_comparison          сравнение многих файлов
external_research             внешнее исследование
independent_review            независимое ревью (writer ≠ judge)
mass_mechanical_inspection    массовая механическая проверка
```

Стартовые пороги (калибруются): разведка ≥ 8 файлов, сравнение ≥ 5 файлов, лог ≥ 500 строк. См.
`tools/delegation_advisor.py`.

## Что возвращается в основной контекст

- краткий вывод;
- релевантные пути;
- evidence;
- открытые вопросы;
- рекомендуемый следующий шаг.

## Что НЕ возвращается

- полный transcript разведки;
- все прочитанные файлы;
- длинные необработанные логи;
- промежуточные рассуждения.

## Как это использует Claude Code

AI Ops не заменяет механизмы рантайма — он говорит, **когда** ими воспользоваться. Разведку/ревью/анализ
логов выносить в сабагента (Task/Explore), а в основную сессию возвращать сводку. Пример совета кита:

```
Разведка затронет ~30 файлов.
Не читать последовательно в основной сессии — результаты осядут в контексте до её конца.
Рекомендация: передать поиск Explore-сабагенту; вернуть карту реализации и релевантные файлы.
```

Кит **СОВЕТУЕТ** (не форсит). Связка с гигиеной сессий — `rules/core/SessionEconomyPolicy.md`
(приоритет: гигиена сессии > делегирование разведки > ограничение итераций > runtime > effort).
