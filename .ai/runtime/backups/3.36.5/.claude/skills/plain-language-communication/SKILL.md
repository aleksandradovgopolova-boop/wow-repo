# Plain Language Communication

Проблема не в многословности, а в архитектуре: внутренний язык системы слишком легко просачивается
в пользовательский интерфейс. `preflight blocked: specification gate unresolved; ApprovalRecord
missing for protected_paths; context payload 128k/150k` — корректное внутреннее состояние и
негодное сообщение человеку.

**Источник истины — не этот файл, а `registry/communication-policy.yaml`.** Контракт `UserMessage`
рендерит КОД (`ai_ops_kit/ui/presenter.py`), потому что соблюдение правил не может зависеть от
того, вспомнила ли модель вызвать скилл. Скилл нужен там, где сообщение формулирует модель, а не
код: он задаёт правила, presenter — форму.

## Четыре вопроса

Каждое сообщение отвечает максимум на четыре, в этом порядке:

1. **Что произошло?** — обязательно.
2. **Почему это важно?** — если последствие неочевидно.
3. **Нужно ли что-то от меня?** — если и только если требуется решение человека.
4. **Что будет дальше?** — обязательно.

Решение стоит ПЕРЕД «что дальше»: человек, у которого спрашивают, должен увидеть вопрос до
описания плана, иначе он читает несогласованное как решённое.

## Правила

- Не начинать со внутреннего состояния — начинать со смысла.
- Переводить события в последствия: не «gate failed», а что теперь нельзя и почему.
- Не перечислять файлы, SHA, ветки и команды, если они не нужны для решения.
- Термин, которого не избежать, расшифровывать при первом употреблении.
- Не показывать 15 успешных проверок там, где достаточно «все проверки прошли».
- Ошибку объяснять через последствие, а не через место в коде.
- Спрашивать только тогда, когда действительно нужно решение человека.
- Давать **рекомендацию**, а не список вариантов без совета.
- Технические детали оставлять доступными по запросу, а не выкладывать сразу.

## Чего скилл НЕ разрешает

**Простой язык — не мягкий.** Недоказанное называется недоказанным; статус `degraded` существует
именно для этого. «Готово» вместо «готово, но не проверено» дороже любого жаргона, и ни одно
правило выше не является основанием сгладить такую формулировку. Перевод меняет ЯЗЫК, а не факты.

## Три уровня, аудитория выбирается один раз

| уровень | для кого | что видно |
|---|---|---|
| `product` (default) | продакт, аналитик, основатель | смысл, результат, решение, следующий шаг |
| `technical` | разработчик, техлид | файлы, API, ветки, тесты, имена гейтов |
| `debug` | отладка кита | всё: gates, SHA, traces, routing, budgets |

Переключается фразой («рассказывай подробнее техническую часть») или
`.ai-ops.yaml -> communication.audience`. Каждое сообщение уровень не переспрашивает.

## Пример

**Плохо:**

```text
preflight blocked: specification gate unresolved; ApprovalRecord missing for protected_paths;
context payload 128k/150k
```

**Хорошо:**

```text
Пока не начинаю разработку.
Задача затрагивает защищённую часть проекта, поэтому мне нужно твоё подтверждение.
Остальное к работе готово.

Нужно от тебя: разрешить изменение модуля авторизации.
Рекомендую: разрешить только чтение агрегированных данных.
Если согласен — начну реализацию и принесу результат на проверку.

Технические детали — по запросу.
```

**Плохо (после осмотра репозитория):**

```text
Detected Python 3.12, FastAPI, SQLAlchemy 2.0, Alembic, React 19, Vite, 14 migrations,
3 CI pipelines. Artifact coverage 8/15. architecture=inferred, data_model=partial.
```

**Хорошо:**

```text
Я разобрался с проектом. Это уже работающий продукт: есть frontend, backend, база данных,
тесты и автоматическая сборка.

Архитектуру и модель данных я могу восстановить сам. А продуктовые цели и приоритеты из кода
понять нельзя — про них спрошу тебя.

Дальше: 5 коротких вопросов, потом соберу базовую модель продукта.
```
