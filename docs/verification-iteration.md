# Проверки при локальной итерации

В этом пилоте доступны `npm run verify:iteration` и `npm run verify:iteration -- --plan-only`.
Нужны Python 3 с зависимостями установленного runtime Kit и зависимости npm по lock-файлу.

Команда сама учитывает staged, unstaged, новые файлы, удаления и обе стороны переименования.
По умолчанию сравнивается HEAD. `--base <ref>` позволяет выбрать согласованную базу задачи;
от неё должны учитываться все изменения задачи. Ошибка чтения git или загрузки runtime
никогда не освобождает от проверок.

Для разрешённой прозы (например README) выполняется lint. Для кода, неизвестного влияния,
конфигурации и Playwright выполняются check, lint, build и полный npm run test.
Отсутствие изменений не считается свидетельством качества и выбирает полный набор.
Любой ненулевой результат останавливает команду и возвращает ненулевой код.

Перед слиянием: `npm run verify:iteration -- --intent merge_candidate`.
Перед релизом: `npm run verify:iteration -- --intent release_candidate`.
Оба намерения требуют полного набора, даже для README. Существующий CI остаётся полным.
Playwright нельзя сузить этим механизмом: адаптер и доказательство охвата ещё не реализованы.

Регрессии обёртки: `python3 scripts/verify-iteration.test.py`.
Планирование и освобождение prose относятся к локальной работе, а не к ускорению всего CI.

Runtime получен из опубликованного тега Kit `v4.9.2`; provenance фиксирует этот тег и release-коммит. Канал остаётся `qualification`. Сохранённый recorder использует существующий модуль `ai_ops_kit.lifecycle.run_report`. Исходный пользовательский checkout этим PR не изменяется.
