# WowRepo — MVP Report

An honest account of the first working MVP.

## What was implemented

- **The controlled-generation engine**: a page-plan schema (Zod,
  `src/engine/page-plan.ts`) as the single source of truth; a repository loader
  (`load.ts`) that ingests a site directory, validates every plan, resolves
  named content, and checks cross-page references; a deterministic renderer
  (`PageRenderer.astro`) that composes pages only from an approved component
  registry. There is no path from a plan to arbitrary HTML.
- **A design system** of semantic CSS tokens (`src/styles/tokens.css`): colour,
  fluid type scale, spacing, layout widths, surfaces, borders, radii, motion,
  focus, breakpoints — the only source of visual values.
- **13 reusable components** plus one genuine interaction island (a breath
  pacer) and a generative **atmosphere** system.
- **Garden** as the first ingested repository (`examples/garden/`): a site
  config, an art-direction document, four validated page plans, and content
  drawn from the confirmed Garden context (canon/draft marked).
- **Four Garden pages**, each with its own plan, rhythm, and composition:
  Manifesto, What Garden is, Principles, Safety & autonomy.
- **A generative atmosphere engine** (`src/scripts/atmosphere.ts`): a shared
  WebGL volumetric-daylight shader (dappled light, god-rays, a rising sun) with
  a per-variant 2D foreground. Used on the Manifesto (a plant that grows as you
  scroll) as the site's signature living moment.
- **Playwright visual/browser tests** across four viewports, **GitHub Actions**
  CI (type-check, lint, build, test), and desktop + mobile **screenshots** for
  all four pages.
- **Seven Claude project skills** and full documentation.

## Screenshots produced

`tests/visual/screenshots/` — desktop (1440) and mobile (390) for all four
pages: `manifesto`, `what-garden-is`, `principles`, `safety`. Regenerated by the
Playwright screenshot tests (in reduced-motion, so the Manifesto shows the
fully-grown tree as a stable still).

## Reusable components (13)

`editorial-hero`, `immersive-opening`, `manifesto-lines`, `longform-prose`,
`principle-statement`, `pull-quote`, `spatial-break` (with an opt-in `breath`
island), `narrative-steps`, `boundary-comparison`, `quiet-callout`,
`closing-reflection`, `next-path`, `related-links`. Each uses tokens only,
works from 320px, supports keyboard + reduced motion, and documents its role.

## Page types supported

Declared: `manifesto`, `concept-explanation`, `principles`, `safety-boundaries`,
`process-ritual`, `place-environment`, `timeline`, `architecture-system`. The
first four are exercised by Garden's pages; the rest render through the same
generic pipeline and simply have no Garden page yet. Extension is documented in
`docs/page-plan-spec.md`.

## Atmospheres

Four variants exist in the engine (`canopy-light`, `sunbeam`, `light-columns`,
`sheltering-glow`). **Only `canopy-light` (the growing tree) ships on a page**
(the Manifesto). During development the other three — being essentially a soft
light/gradient behind editorial content — read as generic "glow behind cards",
so they were pulled: the remaining three pages are deliberately clean,
confident editorial typography instead. This is a real design decision, not an
oversight: an atmosphere earns its place only when it carries meaning and has a
crafted foreground (the plant). The variants remain in the engine for future
pages that warrant them.

## Accessibility status

- Every page has one ordered `h1`; semantic HTML throughout; visible focus
  rings; a skip link.
- Fully usable with **no JavaScript and no WebGL** — atmospheres are decorative
  and hide themselves if WebGL is unavailable; content and navigation are plain
  HTML/CSS.
- **Reduced motion** is honoured everywhere: reveals appear instantly, the
  atmosphere renders a single still frame (no loop), and the breath pacer is
  opt-in and stoppable. No auto-playing motion is aimed at the reader.
- Text stays legible over the atmosphere via a reading veil.
- Verified by Playwright across desktop/laptop/mobile/narrow-mobile: pages load,
  no horizontal overflow, navigation works, critical content visible, no console
  errors.

## Performance status

- Fully **static** output; no server, no database, **no AI call on a page
  view**. Build is ~1.5s for the four pages.
- Client JS is small: a tiny reveal script, the atmosphere island (WebGL +
  procedural, no assets), and one React island only where used.
- The atmosphere runs a `requestAnimationFrame` loop (paused when the tab is
  hidden). On a real GPU this is smooth; under headless **software** WebGL it is
  CPU-heavy, which is why the browser tests run in reduced-motion (also the
  accessible path).

## What is Garden-specific

Everything under `examples/garden/**` (content, page plans, art direction), and
the **token values** in `src/styles/tokens.css` (the warm-paper/botanical
palette). Nothing else.

## What is reusable in WowRepo

`src/engine`, `src/components`, `src/layouts`, `src/scripts`, and the token
*structure/names* in `src/styles`. These carry no Garden content or styling:
components read content via typed props; atmospheres read a variant; a different
repository ships different content + a different token *file* and gets a
coherent, very different site from the same code.

## Known limitations

- Only Garden is supported; there is no generic repository ingestion beyond the
  `examples/<site>` shape.
- Page planning is authored during development (with Claude Code), not generated
  at runtime — by design for this MVP.
- Three atmosphere variants are implemented but unused on pages (see above).
- Full-page screenshots show the fixed atmosphere only in the first viewport (a
  screenshot limitation, not a rendering one — for a real reader it stays in
  view while scrolling).
- Visual regression *snapshots* are not configured (software-WebGL frames are
  not deterministic enough); fresh screenshots are produced instead, as the
  brief allows.

## Technical debt

- Atmosphere shader colours are literals in `atmosphere.ts` rather than read
  from tokens (shaders need raw floats); they mirror the token palette but are a
  second source to keep in sync.
- The atmosphere script is one file with per-variant branches; if more variants
  land it should be split per variant.
- `examples/garden/content/*.yaml` is loosely typed (validated by each
  component defensively, not by a schema) — deliberate for flexibility, but a
  per-component content schema would catch authoring mistakes earlier.

## What should be built next

1. Bring the three unused atmospheres up to the Manifesto's bar (a crafted
   foreground each) or retire them — don't ship bare glows.
2. A per-page content schema keyed to each component's shape.
3. More page types exercised (a real `process-ritual` or `timeline` Garden page).
4. A thin CLI / config so the engine can be pointed at an arbitrary repo.
5. Optional BYOK/local-model planning at build time (architecture already
   allows it; nothing runtime).

## Hypothesis: validated or not?

> AI can understand the meaning of repository content and compose different,
> high-quality pages from a controlled visual language, while keeping the whole
> website coherent.

**Substantially validated for the composition + coherence claim.** The four
pages are genuinely different in rhythm and composition, share one visual
system, and are each described by a validated, HTML-free page plan rendered
deterministically — with no arbitrary markup and no runtime AI.

**Partially open on "high-quality, distinct *experience* per page."** The
signature living atmosphere works and is distinctive; the attempt to give every
page its *own* generative experience did not clear the quality bar and was
(rightly) cut back to one crafted moment plus clean editorial elsewhere. That
"an atmosphere must be crafted, not a gradient" is itself a useful finding. The
controlled-generation architecture made this iteration cheap: changing direction
meant editing plans and token/values, never the engine.
